# AI usage

ChatGPT Codex assisted with the Stage 1 environment inspection, reading the assignment, Laravel scaffolding, and setup documentation. Its output was checked against the assignment PDF, Composer's dependency audit, local PHP and PostgreSQL checks, and the Laravel test command. An initial Laravel 11 scaffold could not install because Composer blocked eligible releases with security advisories; the scaffold was replaced with a PHP 8.2-compatible Laravel 12 project without disabling the audit. Later stages will record additional assistance, verification, and corrections here.

For Stage 2, Codex helped implement the intake migration, validation, integer-based pricing, duplicate handling, PostgreSQL tests, and API documentation. The behavior was checked against the assignment's example premium, all pricing bands, validation cases, database uniqueness, migration results, and the full automated suite. The generic Laravel scaffold's SQLite test settings were insufficient for PostgreSQL-specific behavior, so the suite now selects a dedicated PostgreSQL test database instead of the development database. The candidate should review and explain each implementation decision before submission.

For Stage 3, Codex helped design the submission transaction, explicit transition rules, deterministic local mock, audit schema, and PostgreSQL feature tests. Two incomplete response assumptions were caught by tests: newly created intake rows omitted the migration's default metadata until reloaded, and PostgreSQL JSONB reordered stored response keys between first and repeated submit responses. Both paths now reload persisted values before returning JSON. Verification included Stage 2 regression tests, submission outcome and invalid-transition tests, migration status, formatting checks, and the full test suite. The candidate should review the transaction and state choices before submission.

For Stage 4, Codex helped implement the local provider record, timeout and callback scenarios, keyed retries, reconciliation, read APIs, migrations, and PostgreSQL tests. Review identified an inaccurate Stage 2 README statement that duplicate intake always has the same response body; it now explains that later state and provider fields can change while the request identity and premium snapshot remain stable. Tests exercise each mock scenario, repeat callbacks and retries, conflicts, and unresolved reconciliation. They do not run simultaneous HTTP requests or simulate an independently failing external insurer. The candidate should review the mock's shared-database assumption and explain the limits of its transaction model.

For Stage 5, Codex compared the repository with the assignment PDF and strengthened PostgreSQL feature tests for status filtering across pages and retry requests sent after issuance. The audit distinguishes deterministic duplicate tests from a true simultaneous-request test. The candidate should review the final checklist and verify the intended GitHub remote before publication.

For the end-to-end API investigation, Codex compared the live Laravel connection with the live HTTP list, created one fabricated development request, and verified POST, immediate list/detail GETs, and duplicate POST responses. It added regression tests and a Postman collection with per-scenario fresh idempotency keys. The reported stale collection in the POST response was not reproduced; the actual Postman tab or request configuration that displayed it was not available to inspect.

For the web demo, Codex inspected the existing API routes, responses, models, and README, then added local-only Blade/Tailwind pages that call the established endpoints. It added UI route tests, restricted the unauthenticated mock callback receiver to local/testing, built the frontend assets, and ran the full PostgreSQL suite. The web interface is a demonstration layer; the candidate should review its state-based control gating and verify the layout in a browser before any hosting decision.

For Render preparation, Codex inspected the existing project and Render/Laravel deployment documentation, added a Docker image with locked dependency and Vite builds, Apache port configuration, build-context exclusions, and deployment instructions. It built and smoke-tested the image locally without deploying. The candidate should review the environment variable setup, migrations, and the unauthenticated production API limitation before any public launch.

For the public evaluator demo, Codex reviewed local-only guards and existing mock workflows, added an explicit production demo opt-in, production request limits, synthetic intake validation, a debug-off startup check, tests for the public mock lifecycle, and updated deployment guidance. The candidate should verify an isolated synthetic-only Render database and understand that unauthenticated evaluators share its records. No real insurer or payment service is integrated.
